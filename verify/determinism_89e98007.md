  refresh rather than being byte-checked, so a rule change there is a *republish* of live
  data, not a gate fix — that is the owner's call, logged as CR-89E-01/04.
- Residual, accepted: `f"{x:.2f}"` formatting inside generated HTML. Float formatting is
  specified as correctly rounded from the value itself (`float.__format__`,
  https://docs.python.org/3/library/stdtypes.html#float.__format__) and the inputs here are
  already-pinned artefact values, so no interpreter-dependent summation reaches a page.

## Rules for extending the pin (why this sweep stopped at six files)

1. The pinned rule is `det.sum_`: `math.fsum` when a float is in the input (the rule main chose
   on 2026-11-19 in 78f513d, correctly rounded and identical on every CPython) and exact integer
   addition otherwise, so counts stay `24` and not `24.0` in published JSON. `det.fold` remains
   for reproducing a artefact that was committed under the pre-3.12 fold.
2. `scripts/estimators.py`, `results_feed.py`, `minutes_model.py`, `assemble_canonical.py`,
   `build_app.py`, `model.py` and the site builders are regenerated *on the runner* and their
   output is what the next refresh commits. For those, a rule change can move a published number
   and read as a data change (the game-book artefact is the one that already moved: 0.1088 ->
   0.1087 in 78f513d). Sweep them one file per commit with a byte-diff proof, and pin the
   interpreter in the workflow too — `pages.yml` already pins 3.11 while `refresh.yml` pins
   nothing, which is exactly why PR CI stayed green while the schedule was red (CR-89E-02).
3. The one-shot `capture_official_*` / `round*` scripts in the table above already wrote their
   artefacts; their committed outputs are the record, and re-running them is not part of CI.
   They are listed so nobody re-runs one on a newer interpreter and mistakes the diff for
   moved data.

## What the emulator is, and where it lies

The `sitecustomize` used here replaces `builtins.sum` with Kahan-Babuska compensated summation (a running compensation added at the end). CPython >= 3.12's real `sum()` is Neumaier's variant, which folds the correction in a different order. The two agree on most inputs — including the Washington minutes that started this investigation — but they are not bit-identical in general, so a row that reads 'none' here means 'the emulator did not move it', not 'no interpreter moves it'. For a decision that changes a published number, reproduce on a real >= 3.12 interpreter; the temporary branch-probe workflow in this repository's history is the working method for that.

The round2 row matters for a specific reason: it is the only one where the generator publishes aggregates at full float precision, so the last bit is visible in the JSON. It is covered by `tests/test_round2_2026_11_16.py::Artefacts::test_artifacts_are_byte_identical_to_a_fresh_build`, which `pages.yml:298` runs — green there because pages.yml pins 3.11 — and it is NOT in refresh.yml's nine-suite loop, so today it fails only if something replays that round on a newer interpreter. Rounding at publish (det.dq) would make it interpreter-independent as well as shorter; that is a republish and belongs to the round's owner, not here.

Before this session's fix the same emulation moved `data/rounds/2026-11-17/player_logs_2026-11-15.json` (`.top8_minutes_shares.2026-11-15:WAS.top8[4].share`, 0.1088 -> 0.1087) — the field that has failed the preflight since 2026-11-17. After it, the five replayed generators and the site build reproduce their committed bytes exactly.

Reproduce: `PYTHONPATH=<dir containing a sitecustomize that sets builtins.sum to Neumaier> python3 <generator>`, then `git status`. The emulator used by the test suite is in `tests/test_determinism_89e98007.py`.

## Decision this audit surfaces for the owner

main@78f513d (session f69a11c4) settled the rule question by adopting the correctly-rounded exact
sum and republishing the one field whose 4th decimal the two rules disagree about. This branch
adopts the same rule for all six byte-compared generators and measured it to be byte-neutral for
the other five. What remains a policy question is the rest of the table: a generator whose output
the refresh commits should move to the pinned rule only in a reviewed commit that shows the diff,
because a published number that the pick ledger has hashed must not move as a side effect.
