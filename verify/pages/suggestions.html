1SG-01Strategy evaluation
Three dashboards run three different gate sets (7 gates in /origin/, 6 in /edge/, 7 different gates in /lab/), so 'proven strategy' means three things and none of them is comparable.
  1. Keep three gate sets and publish three leaderboards.
  2. Adopt the /origin/ 7-gate set as canonical and retire the other two.
  3. Adopt the /origin/ 7-gate set, plus require the promotion rule from this site (100 settled picks and a bootstrap interval on Brier skill that excludes zero).
Recommended: Option 3. It keeps the most complete gate set and adds the one control none of the three has: an interval, not a point estimate.
Cost: One afternoon of work. No new data needed.		Awaiting your decision
Approve the gate set and the promotion rule, or name a different one.		source
2SG-02Site structure
Six dashboards disagree with each other and two of them still tell the reader that no picks exist. A visitor cannot tell which page is authoritative.
  1. Keep all six and add a warning banner to each.
  2. Consolidate into one generated site with the other five moved to an /archive/ path marked read-only.
  3. Consolidate and delete the other five.
Recommended: Option 2. Deleting evidence loses the audit trail; keeping six live sites guarantees continued contradiction. Marking the old trees as archived preserves the record without inviting belief.
Cost: One day, mostly moving files and rewriting the root index.		Awaiting your decision
Choose the consolidation target, or confirm the six stay.		source
3SG-03Decision support
Every page shows results but no page shows what to do next. The owner has to read six sites to work out which single decision unblocks the most work.
  1. Leave the pages as they are.
  2. Add a single 'decisions' page ranked by what it unblocks, with the questions and the suggested action on one screen.
Recommended: Option 2, which is what the Decisions page on this site does. It ranks each question by the number of downstream tasks it freezes.
Cost: Already built.		Implemented this session
None.		source
4SG-04Correctness control
Two of the most visible published numbers in the repository were wrong (the parlay joint probability and every pick-card spread label) and nothing caught them before publication.
  1. Rely on review.
  2. Add a numerical self-test to the build that recomputes published values from first principles and fails the build on a mismatch.
Recommended: Option 2. A recomputation that runs on every push is the only control that survives a rushed session. This site implements it.
Cost: Already built.		Implemented this session
None.		source
5SG-05Data freshness
The injury page shows a snapshot that was already superseded when it was published, and nothing stops a stale build from deploying.
  1. Show the report timestamp and let the reader judge.
  2. Refuse to publish a slate whose newest injury report is older than a fixed cutoff before tip-off.
Recommended: Option 2, with the cutoff set per game at the last report published at least 30 minutes before tip-off.
Cost: Small code change; the hard part is the automated pull (Q-05).		Awaiting your decision
Approve the cutoff rule.		source
6SG-06Leaderboard design
The brief asks for a leaderboard that rewards top strategies, but no page defines what is being rewarded, and the current dashboards would rank ineligible entries.
  1. Rank by raw win rate.
  2. Rank by ROI at an assumed price.
  3. Rank by Brier skill against a baseline, multiplied by a confidence factor, with sample size and an interval shown on every row, and no rank for anything that fails a gate.
Recommended: Option 3. Raw win rate is a measure of variance, and ROI at an assumed price is a measure of an assumption. Brier skill with an interval is the only one of the three that measures forecasting ability.
Cost: Small once the gate set is fixed (SG-01).		Awaiting your decision
Approve the ranking rule, or name a different one.		source
7SG-07Provenance
Source links are shown but never checked. A dead or redirected link is invisible until a reader clicks it.
  1. Leave links unchecked.
  2. Add a scheduled link check that fails when an official source stops resolving.
Recommended: Option 2. This environment cannot reach most external hosts from the shell, so the check must run in GitHub Actions where outbound access exists.
Cost: Small.		Recommended - needs approval
Approve adding a scheduled workflow.		source

Recommended: Option 2. Probability to three decimals, prices in American with decimal in brackets, points to one decimal.

Six pipelines recompute overlapping artefacts and no two agree. A reader cannot tell which artefact is upstream of which.
  1. Leave the six pipelines independent.
  2. Declare one pipeline canonical for game results and one for ratings, have the rest consume those artefacts, and let the origin of every number be traceable to one file.
Recommended: Option 2. The 174-game log is already agreed between two independent captures, so it is the natural root of the dependency graph.
