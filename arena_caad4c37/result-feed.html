Before this session every quarter cell in data/app/results_feed.json was null with the note "quarter scores not captured — blank, flagged". The official game books print a "SCORE BY PERIOD" block, so the field was obtainable from an official source after all. A quarter score is written only where the printed quarters sum to the printed final; that test is the game book's own arithmetic, and it is what makes a corrupted extraction detectable instead of usable.

Why three team-sides are still blank

  • GSW in GSW @ SAS — the extraction returned the San Antonio row only; no Warriors period row and no Warriors line-score line exists in it.
  • MEM in MEM @ NOP — the row prints five values against a six-column header (25 · 25 · 27 · 140): Q4 and FINAL are missing and 140 is neither a quarter nor the official final of 142.
  • ORL in MIL @ ORL — the row prints 33 · 30 · 32 · 33 · FINAL 107, which sums to 128. The PDF was fetched twice and returned the identical extraction, so it is not a transient read error.
None of these was filled in. Deriving a missing quarter from the final and the other three quarters would produce a number that looks verified and is not, which is the one failure mode this project cannot afford.

Two rows where the official PDF contradicts itself

In CLE @ MIA and OKC @ LAC the rendered period table disagrees with the line-score text line printed beneath it in the same document. Both were resolved to the text line, because the text line, the team-totals row and the official scoreboard all agree and only one table cell disagrees. The table reading is preserved in the stored excerpts — it was not overwritten. Both are listed on the Flagged for review page.
