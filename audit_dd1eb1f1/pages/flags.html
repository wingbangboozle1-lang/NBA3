F-DD1-01 An injury row with a blank Team cell, and why blank is the right answer
informational — corrected in this audit

Row 18 of the 04:30 AM ET report prints 'Traore, Nolan, Probable, Injury/Illness - Right Calf Tightness / Soreness' with the Game Date, Game Time, Matchup and Team cells empty, because it is the first row of the PDF's second table. This audit's first transcription filled the Team cell in as BKN from the block heading above it. The canonical artefact leaves the cell empty. Leaving it empty is the correct behaviour under the project's no-inference rule, so the audit capture was corrected to blank and the value is published as blank. Consequence for readers: the player's team is not established by this row alone.

Evidence: https://ak-static.cms.nba.com/referee/injury/Injury-Report_2026-11-14_04_30AM.pdf
F-DD1-02 The official schedule prints the same matchup twice inside the 4-day window
needs owner review

NYK@TOR appears on 2026-11-15 (game 0022600241) and again on 2026-11-17 (game 0022600253), both at Scotiabank Arena. POR@MIN appears on 2026-11-16 (game 0022600250) and again on 2026-11-17 (game 0022600254), both at Target Center. This is what the official schedule page prints; it has not been corrected, because the project's rule is to publish the official value and flag the doubt. It matters for the model: a repeat matchup 48 hours apart is not the same game twice, and any rule that treats teams as independent across legs will mis-price it.

Evidence: https://www.nba.com/schedule?date=2026-11-14
F-DD1-03 Two 2026-11-17 game ids are printed out of chronological order
cosmetic

The schedule page prints CHA@LAL at 11:00 PM ET with game id 0022600256 after UTA@LAC at 10:30 PM ET with game id 0022600257. The ids are used as keys, so the stored order follows the page. No value is wrong; a reader sorting by id will see a different order than a reader sorting by tip time.

Evidence: https://www.nba.com/schedule?date=2026-11-14

F-DD1-05 The canonical injury snapshot is 15 minutes behind the newest official file, and the index page itself lags
informational

The canonical artefact publishes the 04:15 AM ET report. The injury-report index listed 04:30 AM ET as the newest 2026-11-14 report when this session read it, and a probe of the 05:30 AM ET file returned an S3 AccessDenied object, so no newer report existed. This session transcribed the 04:30 AM report in full (49 rows) and it is row-for-row identical to what the site publishes. No staleness defect today; the point is that 'newest' has to be re-checked every time, because the index page is cached.

Evidence: https://official.nba.com/nba-injury-report-2026-27-season/
F-DD1-06 Cross-game parlay independence was an assumption; it is now measured, and the totals hint is the one to watch
open — assumption replaced by a measurement

The canonical correlations page publishes 'Two legs in different games' as r = 0.0 with verified = false and the note that independence is an assumption. This session measured within-slate dependence directly: for margin residuals the within-night correlation is -0.014657 (permutation p 0.730454), and for total residuals -0.06954 (permutation p 0.072985). Neither survives a 5% threshold, so the assumption stands for now — but the totals figure is negative and its naive interval excludes zero, which is the direction that would make a cross-game over parlay worth less than independent pricing. Re-measure when the out-of-sample log is larger.

Evidence: https://www.nba.com/games?date=
F-DD1-07 Twelve superseded dashboards are still published next to the canonical one
open — site structure

docs/, site/, lab/, research/, edge/, origin/, dash/, verify/pages/, d01ae7e2/, hub/, dashboard/ and app/legacy/ are earlier sessions' complete sites, each with its own navigation, ID namespace and data snapshot. They are valuable as an audit trail and destructive as a landing page: a reader who lands on one cannot tell which numbers are current. The recommendation filed on the suggestions page is to keep every tree reachable but move all of them behind one dated archive page, so the landing page shows one navigation, one set of numbers and one snapshot date.

Evidence: https://github.com/wingbangboozle1-lang/NBA3
F-DD1-08 A dashboard tile is embedded inside a flagged-item list entry on the landing page
open — presentation defect

On the canonical landing page the 'Highest-severity flags' list item for NF-23 ends with an embedded anchor card linking to dash/index.html. It renders as a flag that is also a navigation tile, inside a list of severity findings. The link itself is fine; its placement makes the page read as if 'Unified dashboard (e40cd215)' were an eighth flagged item. Raised as a change request to the owner of scripts/build_app.py rather than patched here, because that builder owns index.html and a hand edit would be overwritten on the next regeneration.

Evidence: https://github.com/wingbangboozle1-lang/NBA3/blob/main/scripts/build_app.py
