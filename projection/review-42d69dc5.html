Method, stated plainly

  1. Read the file, not a summary of it.
  2. Re-read the official page the file cites (nba.com schedule / standings / team stats / injury index / game book).
  3. Compare character for character when the value is a string or an integer.
  4. If the official page cannot confirm it, leave the value blank, and record the gap here with the source that should have supplied it.

Corrections I had to make to my own work during this session

Listed because a review that only reports other people's errors is not a review. Each of these was wrong when I first wrote it and is corrected in the artefact, not just in this sentence:

  1. Injury-index filing count: I first wrote 78 filings for 11/15. The index lists 76 dated report links across both read chunks. Corrected in the review row R42-11 and on the questions page.
  2. Settlement stamp: the first settlement I wrote stamped 2026-11-15T12:10Z on a game that tipped at 18:00Z. The stamp now comes from the moment the final was confirmed, and settlement_stamp() refuses anything earlier than the end of the game day.
  3. A test that asserted the wrong thing: I wrote a test claiming a renamed arena had no coordinates. The alias is a documented name change and correctly resolves, so the test was wrong, not the data. It now pins the documented behaviour and separately pins the blank-row shape.
  4. A defect that was not a defect: I first called the published 0.0 km travel values an artefact. They are correct — those clubs played at home in their previous game. The real defect was that two surfaces disagreed about whether the number was verified at all (see R42-04).
